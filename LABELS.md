# Task labels

Use one difficulty, one or two kinds of work, and relevant science areas. A label describes the task, not the contributor's ability or career level.

| Group | Labels | Use |
| --- | --- | --- |
| Entry and help | `good first issue`, `help wanted` | Self-contained tasks; additional contributors welcome |
| Difficulty | `beginner`, `intermediate`, `advanced` | Background needed to complete the task |
| Work | `documentation`, `research`, `science`, `data`, `bug`, `enhancement`, `education`, `software` | Expected contribution |
| Science area | `VSWIR`, `TIR`, `multi-sensor` | Topic of the task |
| Coordination | `question`, `discussion`, `needs review`, `mentor available` | Conversation/review state; use mentor label only with a named volunteer |

Do not label routine requests `good first issue` until scope, relevant files, and acceptance criteria are clear. Do not advertise `mentor available` without an agreed mentor. Some reserved labels are created only when first used; avoid labeling an issue just to populate the taxonomy.

Suggested colors when an administrator standardizes display: difficulty `7057ff`, work type `0075ca`, science area `0e8a16`, review `fbca04`. Existing GitHub default labels are retained, even if currently unused.
